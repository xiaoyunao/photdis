## 一、你提出的两个问题，确实应该重新成为主线

因此，第一轮最有意义的结果不是一个“全样本 NMAD”，而是：

> **在什么颜色、亮度、测光误差和可用波段条件下，能给多少对象提供多准确、歧义多大的距离？**

## 三、为什么这几轮会一直转到星团？哪些工作该保留，哪些应该停止

当时追星团有一个合理出发点：**模型与 SPECDIS／SPDist 一致，并不自动说明它的真实距离准确。** 因此，找独立距离检查绝对尺度是必要的。

但随后推进顺序逐渐变成了：

> 一个条件距离模型存在偏差 → 找星团检查 → 样本太少或类型不匹配 → 再检查成员、参数和测光 → 再定义下一个局部验证任务。

问题出在：**全流程还没有形成一个统一的结果，局部验证却不断成为下一步的唯一入口。**

最新提交已经说明，Pal 14 的身份关联较强但参数来源有冲突；新增 64 颗 DECam 暖成员也没有补上当前 K 目标的联合覆盖。因此，这条固定批次已经给出了应有的结论，可以结束。[最新审计结果](https://github.com/xiaoyunao/photdis/blob/60f65d548380423fefc365101eb776a2d6180b9c/docs/giant_parameter_audit_result_v1.md)

**我不建议把最新文档提出的“先给这 64 颗暖星进一步定义阶段和支持范围”继续作为整个项目的下一主任务。**

更合适的安排是：

- 这些对象和结论保留，作为后续验证资料；
- 当前 K 巨星原型标记为尚未完成绝对标定；
- 第一版全流程照常训练、测试和生成内部预测；
- 等整体性能图出现后，再判断哪个误差来源真正限制了最多的科学样本。

这里需要保留的基本要求是身份隔离、正确的训练／测试划分、输入不泄漏标签，以及如实解释验证结果。**不需要把“所有区间已经完美校准、每种巨星阶段已经确认、所有星团偏差已经解释”作为第一版交付条件。**

## 四、我建议的第一版完整框架

这一版应当是一个连续任务：**统一样本 → 训练固定基线 → 整体测试 → 应用到已有天区 → 交付结果。**

### 1. 先明确三种样本角色

| 样本角色 | 选择依据 | 作用 |
|---|---|---|
| **应用母样本** | Legacy 的形态、实测光度、质量和初始天空范围 | 决定最终有多少对象能够进入流程 |
| **训练参照样本** | 应用母样本中具有可靠 Gaia／光谱距离标签的对象 | 学习颜色与类型、光度的关系 |
| **验证参照样本** | 与训练身份及空间区域隔离，有相应参照信息 | 检查模型和完整流程 |

关键是：**应用母样本不要求 Gaia 高信噪比视差、不要求光谱，也不要求 WISE。** 这些条件只决定一个对象能否作为训练或验证参照。

初版直接使用现有 DECam 场，先延续已有高银纬、低消光范围，把主流程跑通。这个范围是首版的验证域，不应写成整个项目永久只做高纬、不能做银盘。北方 BASS/MzLS 使用同样的数据结构，但模型与统计单列。

### 2. 测光筛选先采用现有配置，结果出来后再决定最终门槛

现在没有必要再开一轮寻找“最佳测光误差阈值”的工作。可以直接采用已有规则：

| 项目 | 首版采用的起点 |
|---|---|
| 光学有效性 | grz 各波段有有效实测流量、逆方差、曝光，S/N≥5 |
| 光学质量 | 现有 `grz_clean`：掩膜、邻源贡献、图像边界及饱和等条件 |
| 高精度参考层 | 保留各光学误差 <0.03 mag 的标志，用于训练核心和分层比较 |
| W1 增强层 | W1 通过质量条件且 S/N≥5 |
| W2 增强层 | W1、W2 均通过质量条件且各自 S/N≥5 |
| 应用状态 | 保留每波段误差、缺测、质量失败和训练覆盖状态 |

现有实现已经在 [`photometry.py`](https://github.com/xiaoyunao/photdis/blob/60f65d548380423fefc365101eb776a2d6180b9c/src/photdis/photometry.py) 中完成了这些分层。

**不要把训练参考星的严格误差要求，直接套到全部应用对象上。** 应用样本先按亮度和误差分层评价，再通过验证结果确定哪一层能够进入最终科学目录。

### 3. 训练标签扩大到实际可用的人群，先取消不必要的狭窄星族限制

我建议首版采用一套明确的标签优先规则：

1. 有可靠高信噪比 Gaia 视差的对象，优先使用 Gaia 几何距离构造光度标签。
2. 缺少这样的 Gaia 锚点、但有通过既有质量条件的 SPECDIS 距离时，使用 SPECDIS 作为辅助距离标签。
3. SPDist 保留为交叉目录比较。
4. 每个恒星身份只进入一次，保存标签来源及误差。

统一预测的是 Legacy 的绝对星等：

\[
M_g=g_0-10-5\log_{10}\!\left(\frac{d_{\rm ref}}{\mathrm{kpc}}\right).
\]

不能直接把光谱距离目录中的 Gaia \(M_G\) 当作 Legacy \(M_g\)。SPECDIS 的官方数据模型明确区分了距离 `DIST` 和 Gaia G 波段的 `MG_NN`。:chatgpt-content-reference{index="0"}

这一次，Gaia 训练集合不必预先只剩下冷主序；光谱距离训练集合也不必预先只剩下 4200–5000 K 或已选中的 190 颗。**先使用标签质量支持的较宽人群，按星族分别报告结果。**

这样的混合训练首先得到的是“现有参考样本下的经验光度分布”。Gaia 与 SPECDIS 来源的表现要分别列出，不能把它们当成同等精度的真值，也不能把训练样本的类别比例解释为银河系真实比例。

### 4. 模型先固定为一种简单、已有实现的基线

**我的建议是复用现有的分位随机森林，建立 A／B／C 三套宽人群基线。**

| 模型 | 预测输入 |
|---|---|
| A：grz | \((g-r)_0,(r-z)_0\) |
| B：grzW1 | A ＋ \((z-W1)_0\) |
| C：grzW1W2 | B ＋ \((W1-W2)_0\) |

先固定与已有实现相近的模型复杂度，不同时尝试一排算法。现有 [`quantile.py`](https://github.com/xiaoyunao/photdis/blob/60f65d548380423fefc365101eb776a2d6180b9c/src/photdis/quantile.py) 已能通过叶节点中的训练标签权重描述条件分布，足以作为首版起点。

主线直接学习：

\[
p_{\rm empirical}(M_g\mid \text{颜色}),
\qquad
\mu=g_0-M_g.
\]

这样就不需要先依靠一个高纯度巨星选择器，把所有对象硬分到唯一分支。对于明显存在多个光度解的对象，保留分布或主要模式，避免只输出一个容易误导的平均距离。

与此同时，用已有 DESI 标签检验颜色对**矮星、低重力演化星和过渡类型**的区分能力。精确的 RGB／RC／HB 分类可以后置；当前缺乏可靠标签的类别保留未知状态。

旧 cold-v4、暖演化星和 K 巨星模型继续作为局部对照，它们不必被覆盖或重新解释成全星族模型。

### 5. 有一个必须补上的缺口：真正的全光学 A 模型

这次查代码发现，现有 `A-wide` 虽然只输入 grz，**训练和测试仍然要求对象具有合格 W1**。所以它主要用于同星输入对照，尚未回答无 WISE 的大多数对象表现如何。[现有 wide 实验入口](https://github.com/xiaoyunao/photdis/blob/60f65d548380423fefc365101eb776a2d6180b9c/scripts/giant_wide_run.py)

新 A 模型应当用全部合格光学训练标签，不设 W1 准入条件。这比继续补一个星团检验更直接地影响最终覆盖范围。

## 五、训练和验证应该怎样安排，才能真正回答两个核心问题

### 1. 一套统一的空间分区，贯穿整个流程

同一恒星的重复测量、Gaia 标签和光谱标签必须属于同一分区。训练、参数选择／校准、评价按整场或空间块隔离，A／B／C 使用相同身份规则。

已有天区已经被反复查看，可以作为**首版的发展验证和空间交叉验证**。如实保留这个身份即可，不必为了开始 v0 又去寻找一批“完全未触碰的新星团”。

后续正式科学结论再用额外独立数据检验。旧模型的历史测试结果则继续保留，不改写。

### 2. 必须有两组不同的波段比较

**第一组：同星信息增益。**

在相同训练和测试身份上比较：

- W1 合格集合：A 对 B；
- W1、W2 共同合格集合：A 对 B 对 C。

它回答的是：**多一个颜色，究竟增加了多少信息？**

**第二组：实际应用效用。**

分别允许 A、B、C 使用各自可用的数据，统计：

- A 能处理多少光学对象；
- B、C 在哪些亮度、误差和颜色范围有改善；
- 缺少 WISE 时回到 A，最终保留多少样本；
- 加入 WISE 后，哪些对象改善，哪些没有改善，哪些反而更不稳定。

它回答的是：**这个波段组合在真实样本上值不值得使用？**

初版可以同时保存各可用版本的预测，根据校准／验证结果确定推荐方案，不应预先假定五波段一定优于三波段。

### 3. 验证要同时看条件性能与完整流程性能

以前不少结果回答的是：

> 已经知道它是冷矮星／K 巨星时，颜色能测距多好？

现在还必须回答：

> 测试时只给光度，不给真实类型，模型对整个测试参照集合会输出什么？

因此，完整评价不能只保留事后确认类型正确的对象。误分类型、光度多解、无法给可靠距离和域外对象，都要出现在结果统计里。

验证参照的角色建议如下：

| 参照 | 主要用途 |
|---|---|
| 高信噪比 Gaia | 距离与绝对星等的几何对照 |
| 弱／负 Gaia 视差 | 在视差空间比较，不直接反演成距离真值 |
| SPECDIS | 留出对象的教师尺度一致性，尤其是较远对象 |
| SPDist | 同星交叉目录比较 |
| 已有星团等外部参照 | 额外检查绝对尺度，作为验证报告的一部分 |

SPECDIS 本身使用 Gaia 视差训练；SPDist 使用光谱参数和 Gaia 测光。因此它们与 Gaia 的比较不是三套完全独立真值。这需要在结果中说明，但不妨碍它们参与首版训练和检验。:chatgpt-content-reference{index="1"}

### 4. 主报告应固定为几张能够支持决策的图和表

我建议首版至少交付：

1. **样本流量表**：光度母样本、训练／验证标签、A／B／C 可用数量及未输出可靠距离的原因。
2. **WISE 覆盖图**：随 \(r\)、颜色、光学误差和天区的变化。
3. **同星 A／B／C 性能表**：偏差、NMAD、严重离群比例、区间宽度及覆盖率。
4. **完整测试集合的距离图**：phot-d 对 Gaia-d、SPECDIS、SPDist，并给残差分布。
5. **同一批对象的 CMD 对比**：参考距离与光度预测距离分别构造绝对星等。
6. **精度与覆盖率的关系**：质量门槛逐步收紧后，改善多少、损失多少对象。

所有性能至少按亮度、测光误差和粗星族分层。没有足够参照的区域明确显示“未验证”，不把亮端的表现直接延伸到暗端。

这组结果出来后，才有依据决定：下一项最值得改的是类别简并、标签质量、模型形式、测光误差，还是某一星族的绝对尺度。
