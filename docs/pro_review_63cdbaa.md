## 一、这批图已经把主要失败模式说清楚了

### 1. 演化星的距离失败非常严重，而且发生在模型认为“有支持”的区域

先把最关键的结果放在一起。以下是 **`matched_griz`** 模型，定义

\[
\Delta\mu=\mu_{\mathrm{phot},50}-\mu_{\mathrm{ref}},
\]

严重错误为 \(|\Delta\mu|>1\) mag。贫金属矮星是第一行的一个子集。

| 参考类别或子样本 | 数量 | 中位 \(\Delta\mu\) | 严重错误率 | 68% 区间覆盖率 |
|---|---:|---:|---:|---:|
| 矮星 | 29,865 | \(+0.048\) mag | 1.93% | 74.29% |
| 演化星 | 1,064 | **\(-5.340\) mag** | **96.52%** | **15.88%** |
| 原始 RVS \([\mathrm{Fe/H}]<-1.5\) 的矮星 | 2,858 | **\(+0.386\) mag** | **7.21%** | **49.93%** |

演化星的中位距离比为 \(d_{\rm phot}/d_{\rm ref}=0.0855\)，即相对于参考距离，预测通常只有约十二分之一。这一组 chosen 参考全部来自 SpecDis，没有合格的高精度 Gaia 距离锚；另用 SPDist 比较，方向和幅度也相近，但两个参考目录存在共同数据和选择，不能当作完全独立的真值。[科学结果报告](https://github.com/xiaoyunao/photdis/blob/63cdbaa15e549e45de5ade6faca5e7ea99958cf2/docs/baseline_v1_4_science_result.md)

这张 CMD 最直观：同一批演化星，参考距离给出的绝对星等落在较亮的演化支，预测距离却把它们推到主序附近。因此，一个“看上去很漂亮的预测主序”本身不能证明距离正确。







更有决定性的是新增的标记诊断：

- **支持域内**的 1,042 颗演化星，1,010 颗严重错误，错误率 **96.93%**。
- **未标为歧义**的 826 颗演化星，812 颗严重错误，错误率 **98.31%**。
- 五个达到统计数量门槛的演化星天区，都有约 \(-4.8\) 到 \(-5.6\) mag 的中位残差。[标记、天区与概率诊断](https://github.com/xiaoyunao/photdis/blob/63cdbaa15e549e45de5ade6faca5e7ea99958cf2/docs/baseline_v1_4_science_result.md)

这几个结果共同说明：**继续依靠当前的支持域标记、歧义标记或局部天区排除，无法解决主要问题。** “训练颜色附近有样本”只说明颜色空间有支持，并不保证这些颜色能唯一确定光度。

### 2. 对你的银河晕应用，贫金属矮星偏差也应该成为主评价项

整体矮星的结果容易让人觉得这一部分已经解决，但按原始 RVS 金属丰度划分后，贫金属矮星的中位距离偏大约 **19.4%**，严重错误率从整体的 1.93% 上升到 7.21%。这个结构对银河晕研究比“全样本平均残差又下降一点”更值得关注。[金属丰度诊断及统计](https://github.com/xiaoyunao/photdis/blob/63cdbaa15e549e45de5ade6faca5e7ea99958cf2/docs/baseline_v1_4_science_result.md)

这里还不能直接得出“金属丰度造成全部偏差”的结论：颜色、温度、亮度和参考来源都可能随金属丰度一起变化。而且这次用的是**原始 RVS 金属丰度**，没有应用仓库已有的丰度校正及适用域筛选。这个定义需要补清，下面会说具体怎么改。

但无论最终解释是什么，**下一轮模型必须同时看演化星和贫金属矮星，不能再只用全体对象的总体指标决定是否进步。**

### 3. 扩充数据和加入 \(i\) 的总体改善，已经可以定性为“小幅收益”

同星比较中，扩充训练数据使 A/B/C 的严重错误率下降约 **0.14、0.15、0.19 个百分点**；加入 \(i\) 下降约 **0.14 个百分点**。与此同时，扩充训练数据使演化星的严重错误率分别上升约 **1.12、1.12、2.75 个百分点**。加入 \(i\) 对演化星救回 18 颗、损伤 8 颗，净改善 10 颗。[配对比较](https://github.com/xiaoyunao/photdis/blob/63cdbaa15e549e45de5ade6faca5e7ea99958cf2/docs/baseline_v1_4_science_result.md)

因此，我不会把“继续加更多相同性质的训练样本”排在下一步首位。现有实验已经显示，增加数据量和加入 \(i\) 都没有实质解决光度分支的选择问题。

## 二、对 PDF 的解释需要再收紧一点

这是我认为这次最需要讲清楚的科学判断。

两颗固定选出的演化星失败个例，在参考距离模数附近仍有约 **22.7% 和 36.3%** 的概率质量，但全局中位数落在近距离解。因此，远距离解并没有完全消失。[PDF 个例及积分统计](https://github.com/xiaoyunao/photdis/blob/63cdbaa15e549e45de5ade6faca5e7ea99958cf2/docs/baseline_v1_4_science_result.md)

**不过，这不能直接推出“把远峰权重调高就对了”。**

举一个纯粹说明原理的例子：某个无法进一步区分的观测颜色区域内，如果真实人口是 90% 矮星、10% 巨星，那么一个正确表达这种人口混合的预测，可能给近距离解 90%、远距离解 10%。它的中位数会落在近距离分支，于是那 10% 的真实巨星几乎全部得到错误的中位距离——即使混合概率本身是合理的。

由此需要区分两个问题：

1. **当前单一距离估计是否适用于演化星？**  
   现有结果已经很明确：通常不适用。

2. **当前混合概率是否分配错误？**  
   还需要结合预测时可用的信息、参考样本选择和概率评分来判断。按事后知道的真实类别切开后，某一类 PIT 偏斜或区间覆盖很低，本身不足以证明总体混合概率一定失准。

所以，我会把“支持域内演化星距离失败”保留为强结论，把“问题就是分支权重不对”保留为待检验解释。此前门控实验的负结果仍然有效；不能因为现在看到了远峰，就再走一遍强行提高巨星权重或修改阈值的路线。

**下一步应该检验新增的可观测条件是否能帮助分配概率。** 这正是我建议加入视星等的原因。

## 三、WISE 覆盖问题现在有了更明确的答案

我按新提交中 WISE 的独立交叉统计重新加总，得到下面的结果。比例适用于**原 DECam 母样本的加权抽样**；两列是各波段分别的比例。

| 测量条件 | W1 | W2 |
|---|---:|---:|
| 当前质量条件通过，且 S/N ≥ 5 | **31.51%** | **19.00%** |
| 当前质量条件通过，但 S/N < 5 | **7.49%** | **23.72%** |
| 当前质量条件通过，不限制 S/N | **39.01%** | **42.72%** |

数据来自 [WISE 八格交叉统计](https://github.com/xiaoyunao/photdis/blob/63cdbaa15e549e45de5ade6faca5e7ea99958cf2/manifests/baseline_v1_4_science.json)。

这个结果对下一步排序很有帮助：

**如果保留现有质量条件，改成能够使用低信噪比、负通量的模型，W1 可纳入测量的比例最多从 31.5% 增至 39.0%，增加约 7.5 个百分点。** W2 的潜在增加更大，但 42.7% 是 W2 单波段的比例，不能当作 W1+W2 联合可用率，也不代表所有新增弱测量都能提供有效的测距信息。

同时，W1 有约 **61.0%** 的母样本不通过当前质量条件，其中仅由 FRACFLUX 条件触发失败的就占母样本约 **58.2%**。FRACFLUX 涉及邻源对测光的通量贡献。它与低信噪比高度重叠，但不能把这些对象都解释成“换一种低信噪比算法便能恢复的干净测量”。另一方面，未通过当前 FRACFLUX 门槛，也不等于每颗星的测光都已经被证明不可用。[项目统计](https://github.com/xiaoyunao/photdis/blob/63cdbaa15e549e45de5ade6faca5e7ea99958cf2/manifests/baseline_v1_4_science.json) 

因此：

- **弱 WISE 通量值得做，尤其值得检验 W2 能增加多少实际信息。**
- **它目前不适合作为覆盖大多数无合格 W1 对象的唯一主路线。**
- 39.0% 是保留现有质量规则时的 W1 测量覆盖上限；若希望明显超过这个范围，需要另行评估质量规则和邻源影响。

这已经回答了你最初关心的第二个大问题的一大部分，不需要继续把“WISE 到底覆盖多少”当成一个没有边界的问题。

## 四、下一轮主实验：只给 A 模型增加 \(r_0\)

### 为什么我建议先试这个

当前 A 模型用颜色预测绝对星等，近似学习的是参考样本中的

\[
p_{\rm ref}\!\left(M_g\mid g-r,\ r-z\right).
\]

我建议新增一个对照：

\[
p_{\rm ref}\!\left(M_g\mid g-r,\ r-z,\ r_0\right).
\]

**加入 \(r_0\) 的含义，是允许不同视亮度下的光度分支占比不同。** 它引入亮度条件下的经验星族和距离先验，不增加独立的颜色信息，也不能保证消除真实的双解。

它值得优先试，有三个理由：

- 所有原 grz 应用对象都有这个输入，不增加 WISE 或 \(i\) 的覆盖要求。
- 它直接改变距离 QRF 所使用的信息；此前颜色分类器的 AP 提升，并不会自动改变独立的距离预测路径。
- 它与已经做过的颜色门控、类别平衡和阈值筛选有明确区别，而且实验规模很小。[现有模型输入实现](https://github.com/xiaoyunao/photdis/blob/63cdbaa15e549e45de5ade6faca5e7ea99958cf2/src/photdis/baseline_v0.py)

这里选择 **`expanded_A`** 做对照基线，是为了直接面对覆盖更广的 grz 样本。新旧模型必须在同一批对象上比较，不能拿它与上面 `matched_griz` 的不同样本总体直接比较。

### 实验怎么做

| 项目 | 本轮建议 |
|---|---|
| 基线 | 已冻结的 `expanded_A` |
| 新模型输入 | \((g-r,\ r-z,\ r_0)\) |
| 预测目标 | 保持 Legacy \(M_g\) |
| 训练样本、标签、权重 | 与 `expanded_A` 相同 |
| 算法和超参数 | 保持现有 QRF 设置 |
| 本轮唯一主要变化 | 增加 \(r_0\) |
| 应用范围 | 保持 grz 路径，不附加 WISE 要求 |

实现上有两点需要直接写进任务：

**第一，使用明确的新特征定义。** 不能简单把旧代码的 `dim` 改成 3：旧第三维表示的是 \(z-W1\)。应新增类似 `grz_r0` 的 schema，避免意外变成 B 模型。

**第二，共同传播测光误差。** 每次扰动后，两个颜色与 \(r_0\) 都应由同一组扰动后的 \(g,r,z\) 生成；不要把 \(r_0\) 当作与颜色误差独立的新观测。

### 怎样判断它有没有帮助

复用现有评价程序，重点看下列几个问题即可：

| 评价对象 | 要回答的问题 |
|---|---|
| 演化星 | 距离偏近是否明显减轻？救回多少，又损伤多少？ |
| 矮星、其他/过渡类和未知类 | 演化星改善是否以更多其他对象失败为代价？ |
| 贫金属矮星 | \(+0.386\) mag 的相关偏差是否减轻？ |
| 无 W1、较暗的 grz 对象 | 改善是否落在我们真正希望扩展的应用人群？ |
| Gaia 观测视差 | 包含弱、负视差的预测概率评分是否改善？ |
| 不同参考来源和天区 | 收益是否只集中于某一来源或少数区域？ |

**尤其要检查 Gaia 与 SpecDis 分来源、分亮度的结果。** \(r_0\) 很可能学入参考样本的目标选择和距离分布。如果改善主要发生在两种参考来源交接的亮度范围，就需要谨慎解释为参考选择相关的收益，不能直接称为普适的光度关系。

当前已用于看图和设计实验的九个有效 chosen-test 天区，应作为这次开发比较的数据。若新模型确实有价值，再做独立最终检验；无需把新增完整验证样本变成本次原型的前置条件。现有结果也不能为 \(r=22\)–25 的广泛应用提供精度保证。[测试足迹与应用范围](https://github.com/xiaoyunao/photdis/blob/63cdbaa15e549e45de5ade6faca5e7ea99958cf2/docs/baseline_v1_4_science_result.md)

## 五、现有代码和报告，需要做三处范围很小的修正

### 1. 覆盖图对 cal/test 用错了训练资格条件——这处应该修

`coverage_figures()` 对训练、校准和测试都用了：

```python
class_train_eligible | fit_eligible
```

其中 `fit_eligible` 含有训练专用的光学测光误差限制。这样会把一部分**可以用于验证、但不满足训练入口**的参考星从 cal/test 覆盖图里排除。例如，已有统计中 \(r=22\)–25 的 test 有 7 个 chosen 距离参考，但当前覆盖图的 test 统计为零。[覆盖图实现](https://github.com/xiaoyunao/photdis/blob/63cdbaa15e549e45de5ade6faca5e7ea99958cf2/scripts/baseline_v1_4_science_report.py)；[资格统计](https://github.com/xiaoyunao/photdis/blob/63cdbaa15e549e45de5ade6faca5e7ea99958cf2/manifests/baseline_v1_4_eligibility.json)

建议训练覆盖继续使用真实训练身份；cal/test 覆盖改用实际验证资格，并明确分类参考与距离参考的区别。随之更新“没有 test 参考的母样本比例”。

**这是覆盖图口径的局部问题，不影响已经完成的距离残差评分，也不需要重训模型。**

### 2. 金属丰度结果应明确写成“原始 RVS 丰度分组”

当前代码用了原始 `rvs_feh`，仓库已有的 `rvs_metallicity()` 校正及适用域没有参与这次分组。[绘图选择](https://github.com/xiaoyunao/photdis/blob/63cdbaa15e549e45de5ade6faca5e7ea99958cf2/scripts/baseline_v1_4_science_report.py)；[已有丰度校正](https://github.com/xiaoyunao/photdis/blob/63cdbaa15e549e45de5ade6faca5e7ea99958cf2/src/photdis/audit.py)

这里把原始结果与“校正适用域内”的结果并列一次就够了。现有偏差是值得关注的证据，但还不能据此给全母样本施加一个金属丰度相关的距离修正。

### 3. W1 颜色图需要补清模型来源

`colors_gr_zW1.png` 的残差来自 **`matched_griz`**。这个模型没有使用 WISE；这张图展示的是有合格 W1 的对象在 WISE 颜色空间中的 griz 失败位置。因此，它不能单独证明“把 W1 加入模型后仍没有帮助”。图标题已有模型名，正文再明确这一句即可。[颜色图生成代码](https://github.com/xiaoyunao/photdis/blob/63cdbaa15e549e45de5ade6faca5e7ea99958cf2/scripts/baseline_v1_4_science_report.py)
